# Apache Fineract: system brief

## Purpose

Fineract is an open-source core banking platform intended for financial institutions and innovators serving underserved populations [README.md](../README.md#L8-L11). Branch staff, institutional operators and customer-facing applications use its API for client and group records, loan and deposit portfolios, product configuration, user administration, reporting and the general ledger [functional overview](../fineract-doc/src/docs/en/chapters/architecture/functional.adoc#L3-L40) [system overview](../fineract-doc/src/docs/en/chapters/architecture/system.adoc#L6-L17). It is the transaction and accounting engine behind business applications, rather than a prescribed customer interface [system overview](../fineract-doc/src/docs/en/chapters/architecture/system.adoc#L15-L17).

## Architecture

The repository is a Gradle multi-project Java 21 build, with Spring Boot 3.5.6 and modules for the API provider, core infrastructure, loans, savings, accounting and close-of-business (COB) processing [settings.gradle](../settings.gradle#L45-L70) [build.gradle](../build.gradle#L100-L106) [build.gradle](../build.gradle#L381-L389). The provider exposes API endpoints behind Spring Security filters; COB workers run loan business steps through Spring Batch, including periodic accrual entries [SecurityConfig.java](../fineract-provider/src/main/java/org/apache/fineract/infrastructure/core/config/SecurityConfig.java#L117-L170) [LoanCOBWorkerConfiguration.java](../fineract-provider/src/main/java/org/apache/fineract/cob/loan/LoanCOBWorkerConfiguration.java#L83-L131) [AddPeriodicAccrualEntriesBusinessStep.java](../fineract-provider/src/main/java/org/apache/fineract/cob/loan/AddPeriodicAccrualEntriesBusinessStep.java#L26-L43). Deployment options documented in the repository are an embedded-server JAR, an external-Tomcat WAR, containers and Kubernetes manifests; a single instance enables read, write and batch modes by default, while separate instances can isolate those workloads [README.md](../README.md#L84-L99) [README.md](../README.md#L108-L114) [README.md](../README.md#L119-L148) [instance types](../fineract-doc/src/docs/en/chapters/deployment/instance-type.adoc#L26-L48) [Kubernetes deployment](../kubernetes/fineract-server-deployment.yml#L38-L75). These are supported patterns, **not evidence of a particular live deployment**.

## Data stores

MariaDB/MySQL-compatible databases and PostgreSQL are supported; a tenant store and individual tenant databases are migrated with Liquibase [persistence](../fineract-doc/src/docs/en/chapters/architecture/persistence.adoc#L5-L10) [TenantDatabaseUpgradeService.java](../fineract-provider/src/main/java/org/apache/fineract/infrastructure/core/service/migration/TenantDatabaseUpgradeService.java#L56-L108). The relational database also holds pending external events before asynchronous publication [reliable event framework](../fineract-doc/src/docs/en/chapters/architecture/reliable-event-framework.adoc#L49-L65). Documents may use filesystem or S3-backed storage; S3 support is conditional on configuration [StorageType.java](../fineract-core/src/main/java/org/apache/fineract/infrastructure/documentmanagement/domain/StorageType.java#L24-L27) [S3ContentRepository.java](../fineract-document/src/main/java/org/apache/fineract/infrastructure/documentmanagement/contentrepository/S3ContentRepository.java#L49-L56). This does not establish which option an operator selected.

## Integrations

Inbound applications use tenant-aware HTTP APIs: the security chain applies Basic authentication and endpoint permissions, with optional two-factor checks; OAuth2/JWT bearer-token protection is a separately enabled configuration [SecurityConfig.java](../fineract-provider/src/main/java/org/apache/fineract/infrastructure/core/config/SecurityConfig.java#L117-L165) [AuthorizationServerConfig.java](../fineract-provider/src/main/java/org/apache/fineract/infrastructure/security/config/AuthorizationServerConfig.java#L87-L90) [AuthorizationServerConfig.java](../fineract-provider/src/main/java/org/apache/fineract/infrastructure/security/config/AuthorizationServerConfig.java#L155-L168). Requests identify a tenant through the `Fineract-Platform-TenantId` header [OAuth API example](../fineract-doc/src/docs/en/chapters/security/oauth.adoc#L63-L72). Outbound, enabled external-event producers send Avro-formatted business events to ActiveMQ/JMS or Kafka for downstream consumers; the event framework uses at-least-once delivery [reliable event framework](../fineract-doc/src/docs/en/chapters/architecture/reliable-event-framework.adoc#L21-L39) [ExternalEventJMSConfiguration.java](../fineract-provider/src/main/java/org/apache/fineract/infrastructure/event/external/config/ExternalEventJMSConfiguration.java#L35-L46) [KafkaExternalEventProducer.java](../fineract-provider/src/main/java/org/apache/fineract/infrastructure/event/external/producer/kafka/KafkaExternalEventProducer.java#L41-L69).

## Top 3 operational risks

These are **inferred operational exposures, not confirmed incidents or an assessment of a running installation**:

1. **High — Production security hardening.** Financial/PII data and transaction APIs make inadequate network controls or access configuration a potential fraud and compliance exposure; the project's guidance explicitly calls for a gateway/WAF and defense in depth [security hardening](../fineract-doc/src/docs/en/chapters/security/harden.adoc#L5-L7) [security hardening](../fineract-doc/src/docs/en/chapters/security/harden.adoc#L21-L27). **Mitigation:** require a reviewed production threat model, restricted ingress and regular access-control checks before go-live.
2. **High — COB processing failures.** COB applies accruals and locks loans; failed loans can remain locked, disrupting repayments and delaying accurate financial close [AddPeriodicAccrualEntriesBusinessStep.java](../fineract-provider/src/main/java/org/apache/fineract/cob/loan/AddPeriodicAccrualEntriesBusinessStep.java#L26-L43) [loan locking](../fineract-doc/src/docs/en/chapters/architecture/loan-locking.adoc#L10-L22). **Mitigation:** alert on job failures and stale loan locks, and rehearse controlled recovery.
3. **Med — Duplicate or delayed external events.** At-least-once delivery and broker outages imply consumers may see repeats or lag, potentially leaving partner systems out of sync with booked transactions [reliable event framework](../fineract-doc/src/docs/en/chapters/architecture/reliable-event-framework.adoc#L26-L33) [reliable event framework](../fineract-doc/src/docs/en/chapters/architecture/reliable-event-framework.adoc#L49-L65). **Mitigation:** make consumers idempotent and reconcile event backlog against downstream records.
